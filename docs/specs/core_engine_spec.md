# KiCA 自动机单步演化算法规约 (Algorithm Specification)

## 0. 数据结构与全局状态定义
在任意时刻，系统状态由以下数据结构描述：
*   **`V_A`, `V_B`**: 顶点集合。
*   **`Edges`**: 当前的羁绊边集合，元素格式为 `(v_a, v_b)`。
*   **`Phi`**: 状态字典/数组，存储每个节点的当前因果势（**只读快照**）。
*   **`tau`**: 全局节拍，取值为 `0` 或 `1`。
*   **`Delta`**: 变化量缓存字典/数组，初始全为 `0`（**只写缓存**）。
*   **`Phi_tilde`**: 中间态字典/数组。
*   **`ProperTime`**: 局部原时字典/数组，存储每个节点经历的“体感因果步序”，初始全为 `0`（**独立指标，可选择性持久化**）。

---

## 1. 演化流程 (The 7-Stage Cycle)

### (1) 准备阶段 (Direction Determination)
*   **操作**：读取全局节拍 `tau`，确定当前周期的因果流动方向。
*   **逻辑**：
    *   若 `tau == 0`，定义流动方向为 \(V_A \to V_B\)。对于任意边 `(v_a, v_b)`，源节点 `Source = v_a`，目标节点 `Target = v_b`。
    *   若 `tau == 1`，定义流动方向为 \(V_B \to V_A\)。对于任意边 `(v_a, v_b)`，源节点 `Source = v_b`，目标节点 `Target = v_a`。

### (2) 判定阶段 (Synchronous Evaluation)
*   **核心原则**：**读写严格分离**。所有判定必须基于 `Phi`（只读快照），所有结果必须写入 `Delta`（缓存区）。
*   **操作**：
    1.  初始化所有节点的缓存：`Delta[v] = 0`。
    2.  遍历 `Edges` 中的每一条边 `e = (Source, Target)`：
        *   **条件判定**：如果 `Phi[Source] >= Phi[Target]`。
        *   **缓存写入**：
            `Delta[Source] -= 1`
            `Delta[Target] += 1`
        *   *(注：如果不满足条件，则该边在本回合不产生任何操作)*。

### (3) 处理阶段 (State Application)
*   **操作**：将缓存区的数据一次性结算，生成中间态 `Phi_tilde`。
*   **逻辑**：遍历所有节点 `v`，执行 `Phi_tilde[v] = Phi[v] + Delta[v]`。

### (4) 检测阶段 (Frustration Detection)
*   **操作**：对比旧态 `Phi` 与中间态 `Phi_tilde`，找出发生“因果阻挫”的边，并将其从网络中剥离。
*   **逻辑**：
    1.  初始化一个空列表 `Broken_Edges = []`。
    2.  再次遍历 `Edges` 中的每一条边 `e = (Source, Target)`：
        *   **阻挫判定**：如果该边在阶段(2)中**发生了转移**（即 `Phi[Source] >= Phi[Target]`），并且在结算后**关系反转**（即 `Phi_tilde[Source] < Phi_tilde[Target]`）。
        *   **剥离**：将该边加入 `Broken_Edges` 列表，并从 `Edges` 集合中删除。

### (5) 重新匹配阶段 (Topological Rewiring)
*   **操作**：对 `Broken_Edges` 池中的断裂边进行交叉重组。
*   **逻辑**：
    *   根据配置的匹配策略（如：随机匹配, 最大势差等），将池中的边两两配对。
    *   假设配对的两条旧边为 `(A1, B1)` 和 `(A2, B2)`。
    *   **交叉重组**：生成两条新边 `(A1, B2)` 和 `(A2, B1)`。
    *   将新边加入到全局 `Edges` 集合中。

### (6) 局部原时更新阶段 (Proper Time Evolution)
*   **操作**：根据状态变化和拓扑变化，更新每个节点的局部时间。
*   **逻辑**：
    1.  **提取拓扑变化节点**：从阶段(4)的 `Broken_Edges` 中提取所有涉及的节点，存入集合 `Rewired_Nodes`。
    2.  **事件判定与时间流逝**：遍历所有节点 `v`：
        *   如果 `Delta[v] != 0` （因果势发生改变，即状态事件）。
        *   或者 `v` 存在于 `Rewired_Nodes` 中 （局部连接发生断裂重组，即拓扑事件）。
        *   只要满足上述任一条件，执行 `ProperTime[v] += 1`。

### (7) 结束阶段 (Cycle Conclusion)
*   **操作**：状态固化，节拍翻转。
*   **逻辑**：
    *   将中间态转为正式态：`Phi = Phi_tilde`。
    *   节拍反转：`tau = 1 - tau`。
    *   本周期结束，等待触发下一周期。

## 2. 极端用例说明 (Case Study: The "Super-Node" Drain)

为了向开发人员证明**“阶段(2)引入 Delta 缓存区”**的绝对必要性，我们记录以下用例。

**初始场景设定：**
*   **节拍**：`tau = 0` (方向 \(A \to B\))
*   **节点状态 (`Phi`)**：\(A = 10\), \(B_1 = 8\), \(B_2 = 9\), \(B_3 = 9\)
*   **当前连边 (`Edges`)**：\((A, B_1), (A, B_2), (A, B_3)\)
*   *(即：节点 A 是一个连接了 3 个 B 类节点的“中心节点”)*

**正确执行流（基于上述 7 阶段算法）：**

*   **阶段(1) 准备**：方向为 \(A \to B\)。
*   **阶段(2) 判定**：
    *   查边 \((A, B_1)\)：`Phi[A](10) >= Phi[B1](8)` 成立。`Delta[A] -= 1`, `Delta[B1] += 1`
    *   查边 \((A, B_2)\)：`Phi[A](10) >= Phi[B2](9)` 成立。`Delta[A] -= 1`, `Delta[B2] += 1`
    *   查边 \((A, B_3)\)：`Phi[A](10) >= Phi[B3](9)` 成立。`Delta[A] -= 1`, `Delta[B3] += 1`
    *   **结算 Delta**：`Delta[A] = -3`，`Delta[B1] = 1`，`Delta[B2] = 1`，`Delta[B3] = 1`。
*   **阶段(3) 处理**：
    *   `Phi_tilde[A] = 10 - 3 = 7`
    *   `Phi_tilde[B1] = 8 + 1 = 9`
    *   `Phi_tilde[B2] = 9 + 1 = 10`
    *   `Phi_tilde[B3] = 9 + 1 = 10`
*   **阶段(4) 检测**：
    *   查边 \((A, B_1)\)：旧态 \(10 \ge 8\)，新态 \(7 < 9\)。**判定阻挫，断裂！**
    *   查边 \((A, B_2)\)：旧态 \(10 \ge 9\)，新态 \(7 < 10\)。**判定阻挫，断裂！**
    *   查边 \((A, B_3)\)：旧态 \(10 \ge 9\)，新态 \(7 < 10\)。**判定阻挫，断裂！**
*   **阶段(5) 重组**：这 3 条边全部进入匹配池，等待交叉重组。
*   **阶段(6) 原时更新**：节点 \(A, B_1, B_2, B_3\) 的 `Delta` 均不为 0，且均参与了重组，因此它们的 `ProperTime` 均加 1。
*   **阶段(7) 结束**：`Phi` 更新为 `Phi_tilde`，`tau` 变为 `1`。

**开发避坑指南 (For Developers)：**
如果在代码实现中，没有使用 `Delta` 缓存，而是直接在遍历 `Edges` 时修改 `Phi`（即顺序执行），那么当处理完 \((A, B_1)\) 和 \((A, B_2)\) 后，A 的值会实时变成 8。此时再去处理 \((A, B_3)\) 时，程序会发现 \(8 \ge 9\) 不成立，从而导致 \((A, B_3)\) 无法发生转移。
这会导致**数组的遍历顺序直接影响物理结果**，这是元胞自动机系统中的致命 Bug。因此，**严格遵守阶段(2)与阶段(3)的读写分离**是实现本系统的核心基石。


















# 附: 原始说明


羁绊-因果自动机（简称 KiCA）是一个极简且自洽的离散动力学系统。在我们的框架中，**不存在先验的全局时间背景**，时间的流逝仅仅是系统状态发生因果更迭的宏观错觉。在数学形式上，该自动机完全由三个核心部分严格定义：**状态空间 (State Space)**、**演化规则 (Evolution Rules)** 以及 **初始设定 (Initial Conditions)**。

## 1.1. 状态空间与拓扑骨架 (State Space & Topological Skeleton)
在任意一个因果切片（即系统的“当下”），KiCA 自动机的全局完整状态由一个四元组 \(\mathcal{K}\) 严格定义：

\[ \mathcal{K} = (V, E, \Phi, \tau) \]

*   **\(V\) (Vertices, 顶点)**：永恒存在的离散计算单元。顶点集被严格划分为 \(V_A\) 和 \(V_B\)（且 \(V_A \cap V_B = \emptyset\)）。两者数量存在微小的不对称性：\(|V_A| / |V_B| = 1 + \epsilon\)。
*   **\(E\) (Kizuna Edges, 羁绊边)**：顶点间的无向连接，仅允许在 \(V_A\) 与 \(V_B\) 之间建立（严格的二分图性质）。
    *   *注：若剥离状态值与节拍，我们可定义系统的**全局拓扑骨架**为 \(G = (V, E)\)。对于任意局部顶点子集 \(U \subset V\)，其**闭合子骨架**为 \(G[U] = (U, E_U)\)，而包含与外部环境连接的**开放子骨架**则记为 \(G_{\text{open}}[U] = (U, E_U, \partial U)\)，其中 \(\partial U\) 为边界羁绊边集。*
*   **\(\Phi\) (Causal Potential Function, 因果势函数)**：映射函数 \(\Phi: V \to \mathbb{Z}\)，代表每个节点当前持有的因果势。
*   **\(\tau\) (Global Beat, 全局节拍)**：系统的二元时钟指示器，\(\tau \in \{0, 1\}\)。

## 1.2. 演化规则 (Evolution Rules)
KiCA 自动机的运行，服从且仅服从以下两条底层的代数映射规则。系统的演化体现为从当前态 \(\mathcal{K}\) 到下一个因果态 \(\mathcal{K}'\) 的离散跃迁（\(\mathcal{K} \mapsto \mathcal{K}'\)）：

*   **规则 I：二元节拍与因果势驱动 (Binary Beat & Causal Drive)**
    因果转移的方向由 \(\tau\) 决定，转移的发生由 \(\Phi\) 的梯度驱动。我们定义因果势转移算符 \(\hat{T}\)，它将当前状态值 \(\Phi\) 映射为中间态 \(\tilde{\Phi}\)：
    *   **当 \(\tau = 0\) 时**：因果方向为 \(V_A \to V_B\)。对全网每条边 \((v_A, v_B)\)，若 \(\Phi(v_A) \ge \Phi(v_B)\)，则 \(v_A\) 向 \(v_B\) 转移 1 个单位的 \(\Phi\)。
    *   **当 \(\tau = 1\) 时**：因果方向为 \(V_B \to V_A\)。对全网每条边 \((v_A, v_B)\)，若 \(\Phi(v_B) \ge \Phi(v_A)\)，则 \(v_B\) 向 \(v_A\) 转移 1 个单位的 \(\Phi\)。
    *   所有满足条件的边在当前因果步内**同时**完成转移，生成中间态分布 \(\tilde{\Phi}\)。

*   **规则 II：因果阻挫与局域重写 (Causal Frustration & Local Rewiring)**
    如果在规则 I 的同步更新后，某条边两端的状态值大小关系发生了实质性反转（即转移前 \(\Phi(v_i) \ge \Phi(v_j)\)，转移后中间态 \(\tilde{\Phi}(v_i) < \tilde{\Phi}(v_j)\)），则判定该边发生了“因果阻挫”。
    我们定义拓扑重组算符 \(\hat{R}\) 作用于所有阻挫边构成的集合 \(F \subset E\)：发生阻挫的羁绊边必须立即断裂，并强制与邻近的另一条阻挫边发生交叉重组。旧边 \((A_1, B_1)\) 与 \((A_2, B_2)\) 瞬间断裂，重组为新边 \((A_1, B_2)\) 与 \((A_2, B_1)\)。重组完成后，生成新的羁绊边集 \(E'\)。

*   **状态更新与节拍翻转 (State Update & Beat Flip)**
    完成上述拓扑重组后，全局节拍自动翻转：\(\tau' = 1 - \tau\)。
    系统正式更新到全新的因果态：
    \[ \mathcal{K}' = (V, E', \tilde{\Phi}, \tau') \]
    *(此时，\(\tilde{\Phi}\) 成为新状态的 \(\Phi'\)，系统准备迎接下一次演化映射)*。

## 1.3. 初始设定 (Initial Conditions)
自动机的启动仅需要赋予一组符合状态空间定义的初始态 \(\mathcal{K}_{init}\)。在这个极简框架中，唯一被严格规定和分配的全局资源，只有初始羁绊边的总数量：

\[ |E_{init}| = \max(|V_A|, |V_B|) \]

除此之外，任何满足基础定义的微观赋值都是合法的。初始的拓扑连接 \(E_{init}\) 可以是随机匹配或高度聚集的子图；初始状态值 \(\Phi_{init}\) 的具体分布以及初始节拍 \(\tau_{init}\) 的选择，均不受强制限制。
